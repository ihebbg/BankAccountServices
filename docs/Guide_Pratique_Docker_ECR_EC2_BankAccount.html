Guide pratique appliqué à BankAccountServices
Code .NET → docker build → image locale → docker push → Amazon ECR → docker pull → EC2 → docker run

2. Créer l’instance EC2

Configuration recommandée :

AMI      : Ubuntu Server 24.04 LTS
Type     : t3.micro ou t3.small
Stockage : 20 Go gp3
Clé SSH  : fichier .pem
IP       : Elastic IP recommandée

Security Group

PortUsageSource
22SSHAdresse IP de l’administrateur uniquement
80API HTTP0.0.0.0/0
443HTTPS futur0.0.0.0/0
Le port 443 ne fonctionne que si un certificat et un service HTTPS sont configurés avec ALB, API Gateway ou Nginx. Une simple publication Docker sur le port 80 fournit HTTP uniquement.

Connexion SSH

ssh -i "C:\chemin\cle.pem" ubuntu@IP_EC2

3. Construire l’image Docker sur Windows

Ouvrir PowerShell dans le projet :

cd C:\Users\ihebb\source\repos\BankAccountServices
Get-Item .\Dockerfile
docker info

Construire une image Linux x86_64 compatible avec EC2 :

docker build --platform linux/amd64 -t bankaccount-api:1.0.0 .

Le point final est obligatoire : il représente le contexte de build.

Vérifier et tester

docker images bankaccount-api

docker run -d `
  --name bankaccount-api-test `
  -p 5000:5000 `
  bankaccount-api:1.0.0

docker logs bankaccount-api-test
Invoke-RestMethod http://localhost:5000/api/Customer/liste

docker rm -f bankaccount-api-test

4. Créer ou utiliser le repository ECR

Création si nécessaire :

aws ecr create-repository `
  --repository-name bankaccount-ecr `
  --region us-east-1 `
  --image-tag-mutability IMMUTABLE `
  --image-scanning-configuration scanOnPush=true

Vérifier l’identité AWS locale :

aws sts get-caller-identity

5. Authentifier Docker et pousser l’image

aws ecr get-login-password --region us-east-1 |
docker login `
  --username AWS `
  --password-stdin `
  652197205619.dkr.ecr.us-east-1.amazonaws.com

Résultat attendu : Login Succeeded.

Tag ECR

docker tag `
  bankaccount-api:1.0.0 `
  652197205619.dkr.ecr.us-east-1.amazonaws.com/bankaccount-ecr:1.0.0

Push

docker push `
  652197205619.dkr.ecr.us-east-1.amazonaws.com/bankaccount-ecr:1.0.0
Utiliser un tag versionné ou le SHA Git, pas seulement latest. L’immutabilité garantit qu’une version publiée ne sera pas écrasée.

6. Autoriser EC2 à lire ECR

Créer un rôle IAM :

Trusted entity : AWS service / EC2
Nom            : EC2-ECR-ReadOnly
Permission     : AmazonEC2ContainerRegistryReadOnly

Attacher le rôle :

EC2 → Instance → Actions → Security → Modify IAM role
→ EC2-ECR-ReadOnly

Depuis EC2, vérifier :

aws sts get-caller-identity

L’ARN doit contenir :

assumed-role/EC2-ECR-ReadOnly/...
Ne pas utiliser aws configure sur EC2 en production. Le rôle IAM fournit automatiquement des credentials temporaires.

7. Installer Docker sur EC2

sudo apt update
sudo apt install -y docker.io awscli
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu

Après usermod, se déconnecter puis se reconnecter. Sinon, continuer temporairement avec sudo docker.

8. Authentifier EC2 et télécharger l’image

aws ecr get-login-password --region us-east-1 |
sudo docker login \
  --username AWS \
  --password-stdin \
  652197205619.dkr.ecr.us-east-1.amazonaws.com
sudo docker pull \
  652197205619.dkr.ecr.us-east-1.amazonaws.com/bankaccount-ecr:1.0.0

sudo docker images

Si AWS affiche Unable to locate credentials, le rôle IAM n’est pas attaché ou n’est pas encore disponible.

9. Configurer l’application

L’image contient l’application et appsettings.json, mais les secrets de production devraient être injectés au lancement.

sudo nano /etc/bankaccount.env
ASPNETCORE_ENVIRONMENT=Production
ASPNETCORE_URLS=http://+:5000

ConnectionStrings__DBConnection=Server=ENDPOINT_RDS_REEL;Port=3306;Database=bankaccountdb;User=bankaccount_app;Password=SECRET;SslMode=Required;

Jwt__Key=CLE_JWT_LONGUE
Jwt__Issuer=BankAccountServices
Jwt__Audience=BankAccountClient

S3__BucketName=NOM_BUCKET
S3__Region=us-east-1
S3__Prefix=uploads
S3__PreSignedUrlExpirationMinutes=15
sudo chmod 600 /etc/bankaccount.env

10. Exécuter le conteneur sur EC2

Sans Nginx, publier directement le port EC2 80 vers le port conteneur 5000 :

sudo docker run -d \
  --name bankaccount-api \
  --restart unless-stopped \
  -p 80:5000 \
  --env-file /etc/bankaccount.env \
  652197205619.dkr.ecr.us-east-1.amazonaws.com/bankaccount-ecr:1.0.0

Correspondance :

http://IP_EC2:80 → Docker → port 5000 → ASP.NET Core

--restart unless-stopped redémarre le conteneur après un reboot EC2, sauf s’il a été arrêté volontairement.

Si le nom existe déjà

sudo docker ps -a --filter name=bankaccount-api
sudo docker rm -f bankaccount-api

Puis relancer la commande docker run.

11. Vérifier le déploiement

sudo docker ps -a
sudo docker port bankaccount-api
sudo docker logs --tail 100 bankaccount-api

curl http://127.0.0.1/api/Customer/liste

Depuis le navigateur :

http://IP_EC2/api/Customer/liste

Swagger est disponible seulement si l’environnement et le code l’activent :

http://IP_EC2/swagger/index.html
Dans ce projet, Swagger est activé uniquement lorsque ASPNETCORE_ENVIRONMENT=Development. Ne pas exposer Swagger publiquement en production sans protection.

12. Connexion RDS

Le Security Group RDS doit autoriser :

Type   : MySQL/Aurora
Port   : 3306
Source : Security Group de l’instance EC2

Tester depuis EC2 avec le véritable endpoint RDS :

sudo apt install -y netcat-openbsd default-mysql-client
nc -vz bankaccount-db.xxxxx.us-east-1.rds.amazonaws.com 3306

mysql \
  --host=bankaccount-db.xxxxx.us-east-1.rds.amazonaws.com \
  --port=3306 \
  --user=bankaccount_app \
  --password \
  bankaccountdb

Ne pas écrire littéralement ENDPOINT_RDS : il faut utiliser le DNS affiché dans RDS → Connectivity & security.

13. Déployer une nouvelle version

Sur le poste de développement :

docker build --platform linux/amd64 -t bankaccount-api:1.1.0 .
docker tag bankaccount-api:1.1.0 652197205619.dkr.ecr.us-east-1.amazonaws.com/bankaccount-ecr:1.1.0
docker push 652197205619.dkr.ecr.us-east-1.amazonaws.com/bankaccount-ecr:1.1.0

Sur EC2 :

sudo docker pull \
  652197205619.dkr.ecr.us-east-1.amazonaws.com/bankaccount-ecr:1.1.0

sudo docker rm -f bankaccount-api

sudo docker run -d \
  --name bankaccount-api \
  --restart unless-stopped \
  -p 80:5000 \
  --env-file /etc/bankaccount.env \
  652197205619.dkr.ecr.us-east-1.amazonaws.com/bankaccount-ecr:1.1.0

sudo docker logs --tail 100 bankaccount-api
curl http://127.0.0.1/api/Customer/liste
